# Asset maintenance

These tools regenerate checked-in website assets. They are not part of the site
build or deployment. Keep the originals and review generated images before
committing updated assets.

## Image exports

`optimize_images.dart` is the single exporter for current artwork, avatars, and the
sharing JPEG. It uses the Dart `image` package. Run `dart pub get` first.

```bash
# Inspect all inputs and outputs without writing files.
dart run tools/optimize_images.dart --list

# Regenerate all current variants.
dart run tools/optimize_images.dart

# Regenerate selected groups only.
dart run tools/optimize_images.dart --only homepage flock nest
dart run tools/optimize_images.dart --only sharing avatars

# Locate high-resolution originals outside the website repository.
dart run tools/optimize_images.dart --only about blog --branding-dir ../branding

# Preview exports without changing the served images.
dart run tools/optimize_images.dart --only about blog --output-dir /tmp/flock-image-preview
```

Groups are `homepage`, `flock`, `nest`, `about`, `blog`, `sharing`, and `avatars`.
The default exports all groups. About and Blog read their originals from
`../branding` by default; the other groups use originals retained under
`source/images/`. If branding originals are unavailable, select the other groups
with `--only`. Missing inputs stop the export before any files are written.
You can also repeat `--only` or use comma-separated groups.

Export settings and source filenames live in the `exports` list. When replacing
artwork, update its entry. Preserve the exact sizes of the completed flight
sprites because they match the hero's SVG coordinates. Retired images are not
regenerated by this tool.

The encoders use cubic resizing, exact alpha for WebP, and explicit lossy/lossless
settings. Dart and Pillow do not produce byte-identical outputs: compare quality
and file sizes in a preview directory before replacing existing assets.

## Other maintenance tools

| Tool | Purpose | Dependencies |
| --- | --- | --- |
| `capture_social_image.cjs` | Capture the built homepage hero with blank commit cards, saving the PNG master and sharing JPEG. | Node.js, Playwright, Chromium |
| `generate_favicons.dart` | Recreate favicon, app-icon, and Safari mask files from the full-size Flock logo. | Dart `image` package |
| `export_nest_logo.dart` | Export the small Nest logo from its high-resolution design master. | Dart `image` package |

The Dart logo exporters support preview locations too:

```bash
dart run tools/generate_favicons.dart --output-dir /tmp/flock-favicons
dart run tools/export_nest_logo.dart --output /tmp/nest-logo.png
```

Both accept `--source` to choose a different original. `image_utils.dart` is a
shared library for these tools, not a script to run directly. Test the tools with
`dart test test/image_tools_test.dart`.

Build the site before capturing its sharing image, then rebuild afterward to
publish the new files. Set `FLOCK_CHROME_PATH` to use an existing Chrome binary.
The capture tool replaces the master; `dart run tools/optimize_images.dart --only sharing` can
re-export its JPEG without recapturing the hero.

Obsolete design helpers are removed rather than maintained alongside these tools.
